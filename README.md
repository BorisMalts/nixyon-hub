# Nixyon Hub

Nixyon Hub: сервер сборок и замеров для [Nixyon](https://github.com/Andre-wb/Nixyon):
приложения, которое расшифровывает записи встреч на телефоне. Хаб собирает APK из
репозитория Nixyon, гоняет его CI на своём раннере, проверяет качество распознавания на
наборах записей и обучает классификатор «ребёнок или взрослый». Всё это открывается в
браузере, с телефона тоже.

Хаб сам ничего не считает. Он клонирует Nixyon, запускает его скрипты и утилиты замера
(`quality_eval`, `eval`, `child_adult_eval`) и показывает их вывод. Формулы WER, DER и RTF
лежат в Nixyon, в крейтах `nixyon-metrics` и `nixyon-eval`, и описаны в разделе
[«Замер качества»](https://github.com/Andre-wb/Nixyon#замер-качества) его README.

Лицензия проекта не выбрана.

## Возможности

- **Вход.** Почта и пароль. Регистрации нет: учётные записи заводит владелец командой на
  сервере.
- **Сборки.** «Обновить код» (`git pull` репозитория Nixyon) и «Собрать APK» с журналом
  вживую. Список APK с датой, коммитом и размером, скачивание сжатым gzip и QR-код ссылки
  для телефона. Хранятся 20 последних APK. История заданий с журналами: 30 дней или 500
  последних, что раньше.
- **Тесты.** Прогоны CI Nixyon на раннере хаба: шаги, время, журналы шагов, отбор упавших
  и по ветке, ссылка на прогон в GitHub.
- **Качество.** Запуск `quality_eval` по выбранным наборам записей: у каждого набора
  галочка и сколько минут звука взять, расчёт времени прогона, ход с точностью 0,1 %.
  Отчёт `report.md` прямо на странице, история WER по коммитам, худшие клипы с
  прослушиванием и ручными пометками. На скачивание `report.md`, `summary.json` и клипы.
- **Обучение.** Обучение классификатора «ребёнок или взрослый» утилитой `child_adult_eval`
  на выбранных наборах: ход по клипам, журнал, отчёт и веса на скачивание. Признаки голоса
  наружу не отдаются.
- **Terminal.** Терминал в браузере внутри контейнера сборки (xterm.js).
- **Статистика.** Время сборок и тестов по дням, доля упавших прогонов, самые долгие
  шаги, кто сколько запускал, размер APK.
- **Зеркало моделей.** Модели, которые скачали скрипты Nixyon, лежат под своей SHA-256 и
  открыты без входа (`/models/<sha256>`). Скрипты загрузки Nixyon сначала берут файл
  отсюда и сверяют сумму, а если зеркало недоступно, качают из исходного места.

Интерфейс только на русском. На телефоне вкладки внизу, на широком экране колонкой
слева.

## Как устроен

| Компонент | Что делает | Сети |
|---|---|---|
| `nixyon-hub` ([`hub/`](hub)), Rust и axum | вход, сессии, страницы, раздача APK и отчётов, прокси терминала и команд к агенту | `nixyon_edge`, `nixyon_internal` |
| контейнер сборки с агентом `nixyon-agent` ([`agent/`](agent)) | клон Nixyon, сборка APK, проверка качества, обучение, терминал (PTY) | `nixyon_internal` без выхода наружу, `nixyon_egress` в интернет |
| раннер GitHub Actions с `nixyon-ci` ([`deploy/runner/`](deploy/runner)) | тесты Nixyon из его `.github/workflows/ci.yml`, отчёты шагов для хаба | `nixyon_egress` |
| обратный прокси | TLS и домен; подключается к сети `nixyon_edge` | `nixyon_edge` |

- **Хаб и агент.** Хаб не управляет Docker и не видит его сокет. Команды и терминал идут
  к агенту в контейнере сборки по внутренней сети с секретным токеном.
- **Раннер отдельно.** Раннер исполняет код любого пуша в Nixyon, поэтому живёт отдельно
  от контейнера сборки: без ключа развёртывания и токена агента, со своими кэшами, только
  с выходом в интернет. Тест не подменит кэш, из которого собирается APK.
- **Ядра и память.** Контейнер сборки и раннер делят один пул `nixyon.slice`: вместе не
  больше 14 ядер и 24 ГБ, с пониженным весом. Тяжёлые шаги (сборка APK, проверка
  качества, обучение, шаги тестов) идут по очереди через общую блокировку.
- **Отчёты тестов.** Хаб читает их только на чтение. Отчёты пишет непроверенный код,
  поэтому поля ограничены по длине и набору символов, ссылка только на
  `https://github.com/`, вывод только текстом.
- **Данные.** Учётные записи, сессии и журнал событий в SQLite (`hub.db`). APK, журналы
  заданий, отчёты качества и обучения в томе `artifacts`. Наборы записей для замеров
  кладёт владелец в `/opt/nixyon/datasets`, контейнер сборки видит их только на чтение.
  Свободные наборы для обучения контейнер сборки качает сам в том `training-data`.

## Защита

- **Пароли и сессии.** Argon2id. Лимит: 10 попыток входа в минуту с IP, после 5 неудач
  учётная запись закрыта на 15 минут. Сессия: 32 случайных байта, в базе только SHA-256;
  cookie `__Host-` с HttpOnly, Secure и SameSite=Strict; простой 12 часов, предел 7 дней.
- **Запросы.** SameSite=Strict и проверка `Origin` у всех изменяющих запросов и
  WebSocket. Тело запроса до 16 КБ, лимиты частоты в самом хабе. Клиенту общий текст
  ошибки и id запроса, подробности в журнал.
- **Журнал событий.** Только на вставку: правка и удаление запрещены триггерами базы.
  Пишутся вход, неудачный вход, выход, сборка, обновление кода, открытие и закрытие
  терминала, с IP и устройством. Содержимое терминала не пишется.
- **Контейнеры.** Контейнер сборки и раннер под gVisor (`runsc`), все capabilities сняты,
  `no-new-privileges`, не root, предел процессов. Правило `DOCKER-USER` не пускает
  подсети Nixyon в частные адреса и на SSH хоста. Исключение: подсеть с выходом в интернет
  ходит на внешний адрес хоста по порту 443, как любой человек из интернета, чтобы CI брал
  модели с зеркала.
- **Файлы.** APK, отчёты и клипы отдаются по id из списка; файлы открываются без перехода
  по символическим ссылкам.

## Требования

- Сервер на Linux с Docker и Docker Compose, рантайм gVisor (`runsc`), systemd.
- Обратный прокси с TLS, который ходит в сеть `nixyon_edge` и отдаёт домен хаба на
  `10.233.0.10:8080`. Сеть `nixyon_edge` создаёт стек прокси: без неё `install.sh up`
  останавливается.
- Репозиторий Nixyon на GitHub и права администратора в нём: ключ развёртывания и токен
  регистрации раннера выдаёт владелец репозитория.
- Для разработки: Rust 1.95 с `rustfmt` и `clippy`, Python 3 для тестов раннера.

## Установка на сервер

Все команды от root. Код хаба лежит в клоне этого репозитория `/opt/nixyon/hub`.

1. Клон хаба:
   ```sh
   git clone https://github.com/BorisMalts/nixyon-hub.git /opt/nixyon/hub
   ```
2. Папка состояния, токен агента и ключ развёртывания:
   ```sh
   bash /opt/nixyon/hub/deploy/install.sh prepare https://<домен хаба> git@github.com:<владелец>/<репозиторий>.git
   ```
   Скрипт печатает открытый ключ. Владелец репозитория Nixyon добавляет его в Settings,
   Deploy keys, только на чтение.
3. Запуск:
   ```sh
   bash /opt/nixyon/hub/deploy/install.sh up
   ```
   Скрипт клонирует Nixyon, собирает образ сборки Android из его `docker/android`, образы
   хаба, контейнера сборки и раннера, ставит правила сети и службу systemd, запускает
   стек и ждёт, пока хаб станет `healthy`.
4. Учётные записи, пароль из stdin:
   ```sh
   printf '%s\n' '<пароль>' | bash /opt/nixyon/hub/deploy/install.sh user-add <почта>
   ```
5. Раннер. Владелец репозитория Nixyon открывает Settings, Actions, Runners, New
   self-hosted runner и берёт токен из команды `./config.sh --token ...`; токен живёт час.
   ```sh
   printf '%s\n' '<токен>' | bash /opt/nixyon/hub/deploy/install.sh runner-register
   ```
   Раннер появляется в GitHub с меткой `nixyon`; workflow Nixyon берёт его по
   `runs-on: [self-hosted, nixyon]`. Если репозиторий публичный, в Settings, Actions,
   General стоит включить одобрение запусков для внешних участников.
6. Ключ подписи APK (необязательно). Без него хаб создаёт свой отладочный ключ. Чтобы APK
   из хаба ставился поверх собранного на ноутбуке, передайте свой:
   ```sh
   bash /opt/nixyon/hub/deploy/install.sh debug-keystore < ~/.android/debug.keystore
   ```

Проверка снаружи: вход, «Обновить код», «Собрать APK», скачивание, терминал.

## Обновление

```sh
git -C /opt/nixyon/hub pull --ff-only
bash /opt/nixyon/hub/deploy/install.sh up
```

`up` можно запускать повторно: он обновляет клон Nixyon, пересобирает образы и
пересоздаёт только изменившиеся контейнеры. Тома с данными не трогаются.

Чтобы переключить хаб на другой репозиторий Nixyon, поменяйте `NIXYON_REPO_URL` и
`NIXYON_RUNNER_URL` в `/opt/nixyon/.env`, добавьте ключ развёртывания в новый репозиторий,
удалите `/opt/nixyon/src`, запустите `up` и зарегистрируйте раннер заново.

## Настройки

`/opt/nixyon/.env` пишет `install.sh prepare`:

| Переменная | Что задаёт |
|---|---|
| `NIXYON_PUBLIC_ORIGIN` | публичный адрес хаба, по нему проверяется `Origin` |
| `NIXYON_REPO_URL` | ssh-адрес репозитория Nixyon |
| `NIXYON_RUNNER_URL` | адрес репозитория для раннера; выводится из `NIXYON_REPO_URL` |
| `NIXYON_STATE` | папка состояния, `/opt/nixyon` |

Остальное задано в [`deploy/compose.yaml`](deploy/compose.yaml):

| Переменная | Где | Что задаёт |
|---|---|---|
| `NIXYON_HUB_LISTEN` | хаб | адрес, который слушает хаб |
| `NIXYON_HUB_DB` | хаб | путь к `hub.db` |
| `NIXYON_AGENT_ADDR`, `NIXYON_AGENT_TOKEN_FILE` | хаб | адрес агента и файл с его токеном |
| `NIXYON_ARTIFACTS_DIR` | хаб, агент | APK, журналы, отчёты |
| `NIXYON_TRUSTED_PROXIES` | хаб | адреса прокси, которым верится заголовок с IP клиента |
| `NIXYON_CI_REPORTS_DIR` | хаб | отчёты шагов CI |
| `NIXYON_MODELS_DIR` | хаб | зеркало моделей для раздачи |
| `NIXYON_AGENT_ALLOWED_PEERS` | агент | с каких адресов агент принимает соединения |
| `NIXYON_HEAVY_LOCK` | агент | общая блокировка тяжёлых шагов |
| `NIXYON_DATASETS` | агент | наборы записей для проверки качества |
| `NIXYON_MODELS_MIRROR_DIR` | агент | куда агент кладёт скачанные модели для зеркала |
| `NIXYON_TRAINING_DATA` | агент | наборы для обучения |

Команды хаба внутри его контейнера:

```sh
docker exec -it nixyon_hub nixyon-hub user add <почта>
docker exec -it nixyon_hub nixyon-hub user password <почта>
docker exec -it nixyon_hub nixyon-hub user remove <почта>
docker exec -it nixyon_hub nixyon-hub user list
```

## Проверки

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cd deploy/runner && python3 -m unittest test_nixyon_ci test_nixyon_live_eval
```

- `hub/tests/http.rs`: HTTP хаба целиком, от входа и сессий до раздачи файлов и отчётов.
- Модульные тесты рядом с кодом в `hub/src` и `agent/src`.
- `deploy/runner/test_*.py`: отчёты шагов CI и прогон живых записей.

## Структура репозитория

```
hub/                 сервер хаба
  src/               вход, сессии, маршруты, отчёты, зеркало моделей
    routes/          обработчики HTTP по разделам страницы
    cli/             команды хаба, кроме serve и user
  ui/                страницы: HTML, CSS, JS без сборки, xterm.js своей копией в vendor/
  tests/             тесты HTTP
agent/               агент в контейнере сборки
  src/server/        задания, шаги, очередь, терминал, наборы для замеров и обучения
  src/protocol/      протокол хаба и агента
deploy/              развёртывание
  compose.yaml       хаб, контейнер сборки, раннер, тома и сети
  install.sh         установка и обновление
  uninstall.sh       полное удаление
  firewall.sh        правила DOCKER-USER для подсетей Nixyon
  *.Dockerfile       образы хаба, контейнера сборки и раннера
  runner/            запуск и регистрация раннера, отчёты шагов CI
```

## Удаление

```sh
bash /opt/nixyon/hub/deploy/uninstall.sh
```

Скрипт убирает контейнеры, тома, образы, правила сети, службу systemd и папку
`/opt/nixyon` вместе с клоном хаба. Блок прокси и сеть `nixyon_edge` убираются в стеке
прокси отдельно. Раннер в GitHub удаляет владелец репозитория Nixyon в Settings, Actions,
Runners.
